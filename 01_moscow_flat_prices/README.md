# Проект 1. Стоимость квартир в Москве

**Задача:** для каждой квартиры из `data/test.csv` (10 127 строк) предсказать `Price`.
**Метрика:** ошибка между логарифмом прогноза и логарифмом факта. Чем меньше, тем лучше.
**Лидерборд:** лучший результат сейчас 0.17372. Отправка одна, финальная, поэтому выбирать решения будем только по кросс-валидации.
**Запуск:** финальная тетрадь `solution.ipynb` содержит всю работу от сырых данных до результата и выполняется в GitHub Actions не дольше 10 минут.

## Структура

```
data/          исходные файлы конкурса: train.csv, test.csv, sample_submission.csv
imports/       внешние файлы импорта с описанием (imports/README.md)
service/       служебные тетради, которые создают файлы в imports/
solution.ipynb финальная тетрадь: вся работа от данных до сабмита (делаем в конце)
REPORT.md      отчёт: какие методы использованы и почему (делаем в конце)
submissions/   файлы с предсказаниями
experiments/   черновые эксперименты, удаляются в конце проекта
```

## Что уже известно

| Факт | Почему важно |
|---|---|
| Бустинг на сырых признаках даёт RMSE(log) ≈ **0.179** на 5-fold CV (`experiments/00_quick_baseline.py`) | Лидерборд, скорее всего, считает именно **RMSE** логарифмов: 0.174 близко к 0.179, а MSE у той же модели 0.032. Значит, CV можно сравнивать с лидербордом напрямую |
| Правило «средняя цена м² района × площадь» даёт 0.305, константа — 0.890 | Нижняя планка для сравнения |
| `log(Price)` распределён почти нормально. Цена от 1,7 млн до 2,3 млрд ₽, площадь до 1703 м² | Учим модель на логарифме. Выбросы нужно разобрать отдельно |
| Room принимает значения 1/2/3/5, а «4» есть только у 32 квартир. Средняя площадь при Room=5 составляет 214 м² | Похоже, 5 означает «4+», то есть многокомнатную |
| Пропуски: Balcony 32%, Lift 23%, Walls 15%, Age 1%, District/Okrug 1%. В train и test доли одинаковые | Пропуск может сам по себе нести информацию о цене |
| 2358 строк train (1103 группы) полностью совпадают по признакам, цены внутри группы отличаются на ~4% | Повторные объявления. Двойник в train есть у 5,8% строк train и у 5,6% строк test, то есть test устроен так же |
| У 569 строк test есть точная копия признаков в train | Можно использовать как «подсказку» при предсказании |
| 120 районов, каждый лежит в одном округе. Новых районов в test нет | Округ однозначно восстанавливается по району |
| Цена м² не меняется с ростом Id, adversarial AUC train против test = 0.498 | Временного сдвига нет, разбиение train/test случайное |
| Порядок Id не случаен: соседние по Id строки часто из одного дома, порядок test согласован с train | Не используем по решению аудита: это артефакт подготовки файлов |
| «Псевдо-дом» (район + этажность + стены + тип жилья): разброс цены м² 0.187 против 0.292 внутри района | Сильный кандидат в признаки (фаза 3) |
| Скорость раннера Actions: LightGBM 5 фолдов ≈ 20 с, XGBoost ≈ 40 с, CatBoost ≈ 3 мин | Бюджет финальной тетради 10 минут |
| Внешние данные: координаты центров 120 районов собраны из английской Википедии (`service/collect_district_coords.ipynb` → `imports/district_coords.csv`, 5 районов вручную) | Расстояние до центра коррелирует со средней ценой м² района на −0.77 |

## План работы

**Как работаем:**
1. Первые проверки и план фаз согласуются один раз.
2. Перед фазой я выношу на обсуждение только методы, допустимость которых под вопросом, и любой новый внешний импорт (данные из интернета, другие тетради). Остальное делаю по своей рекомендации.
3. После фазы кратко рассказываю о результатах.

Вариант принимается при приросте CV ≥ 0.001 на фиксированных фолдах. Каждое решение должно иметь содержательное объяснение, а не только прирост метрики. Число шагов в фазе не ограничено.

**Решения аудита (что допустимо):**

| Допустимо | Не используем |
|---|---|
| Логарифмирование, винсоризация, инженерные признаки, target encoding (out-of-fold) | Признаки из порядка Id: это эксплуатация подготовки файлов, а не моделирование цены |
| Группировки по признакам: двойники, «псевдо-дом» | Стекинг |
| Классические бустинги (LightGBM, CatBoost, XGBoost), линейные модели, среднее моделей | Нейросети |
| Optuna и SHAP с пояснением в решении | Ручная подстановка цены дубля после прогноза |
| Общие внешние данные: координаты районов, открытые датасеты с GitHub | Узкоспециальные данные, собранные под задачу |
