# Проект 1. Стоимость квартир в Москве

**Задача:** для каждой квартиры из `data/test.csv` (10 127 строк) предсказать `Price`.
**Метрика:** ошибка между логарифмом прогноза и логарифмом факта. Чем меньше, тем лучше.
**Лидерборд:** лучший результат сейчас 0.17372. Отправка одна, финальная, поэтому выбирать решения будем только по кросс-валидации.
**Запуск:** финальная тетрадь `solution.ipynb` должна выполняться в GitHub Actions за 5–10 минут.

## Структура

```
data/          train.csv, test.csv, sample_submission.csv
experiments/   черновые скрипты и тетради (00_..., 01_..., ...)
submissions/   файлы с предсказаниями
solution.ipynb финальная тетрадь (делаем в самом конце)
```

## План 1. Общий порядок работы

Каждый шаг устроен одинаково: я предлагаю варианты со своей рекомендацией → проверяю их быстрыми экспериментами в `experiments/` → показываю цифры CV → ты выбираешь → решение записывается в журнал внизу.

| Шаг | Что делаем | Что получаем на выходе |
|---|---|---|
| 0 | Инфраструктура: `requirements.txt`, фиксированные seed, общий модуль для CV | Одинаковые условия для всех экспериментов |
| 1 | **EDA**: распределения, связи с ценой, пропуски, дубли, выбросы, сравнение train и test | Список гипотез для признаков и очистки |
| 2 | **Схема валидации**: как делить на фолды, как бороться с дублями, насколько стабилен CV | Надёжная оценка, которой можно верить без лидерборда |
| 3 | **Очистка и подготовка**: таргет, выбросы, пропуски, кодирование категорий | Базовый пайплайн и baseline-скор |

## План 2. Подробно по этапам: варианты для каждого шага

### Этап 1. EDA

1. **Таргет.** Распределения `log(Price)` и `log(Price/Size)`. Что удобнее моделировать: цену или цену квадратного метра?
2. **Числовые признаки.** Связь Size, Floor и FloorsTotal с ценой м². Нелинейности: первый и последний этаж, высотки, «пятиэтажки».
3. **Категории.** Цена м² в разрезе Okrug, District, Walls, Age, Balcony, Lift. Взаимодействия: монолит × новостройка, кирпич × ЦАО и т. п.
4. **Пропуски.** Связана ли сама пропущенность с ценой? Одни и те же ли строки теряют сразу несколько признаков?
5. **Аномалии.** Комнатность против площади (1-комнатная на 1703 м²), экстремальная цена м², Room=4. Это ошибки или реальная элитка?
6. **Дубли.** Как устроены группы повторов, насколько различаются цены внутри группы. Это шум, который никакая модель не уберёт.
7. **Train и test.** Adversarial validation: если классификатор не отличает train от test, случайного KFold достаточно.
8. **«Псевдо-дом».** Сколько квартир делят одинаковые District + FloorsTotal + Walls + Age. Это приближение к одному зданию и потенциально очень сильный признак.

### Этап 2. Валидация

| Вариант | Плюсы | Минусы |
|---|---|---|
| KFold(5), shuffle | Просто | Дубли попадают в разные фолды, скор оптимистичен |
| **GroupKFold по группам дублей** | Честная оценка | Нужно определить группы |
| Stratified по квантилям цены | Ровнее распределение дорогих квартир по фолдам | Сам по себе дубли не решает |
| Repeated (3×5) | Видно разброс между запусками, проще отличить реальный прирост от шума | Дольше считать |

Рекомендация: **StratifiedGroupKFold** (группы — дубли, страты — квантили цены), повтор с 2–3 сидами. Для сравнения будем смотреть и на обычный KFold. Учтём, что test тоже содержит копии train, поэтому «правильная» схема для этой задачи может оказаться посередине. Это обсудим отдельно.

### Этап 3. Очистка и подготовка

- **Таргет:** `log(Price)` или `log(Price/Size)` (тогда прогноз = ppm × Size). Сравним на CV.
- **Выбросы:** (а) оставить, (б) удалить из обучения явные ошибки, (в) уменьшить им вес, (г) Huber-лосс. Удаляем только из train, а оценку CV считаем по всем строкам.
- **Дубли:** (а) оставить, (б) свернуть в одну строку со средней ценой, (в) оставить с уменьшенным весом.
- **Пропуски:** категория «unknown» для категориальных. Okrug восстанавливаем по District. Флаги пропуска.
- **Room:** трактовать 5 как «4+». Признак «4/5».
- **Категории:** нативная обработка в CatBoost и LightGBM, one-hot для линейных моделей, target encoding (обязательно out-of-fold).

### Этап 4. Признаки

1. **Инженерные:** `log(Size)`, Size/Room, Floor/FloorsTotal, первый этаж, последний этаж, этажность группами (≤5, 6–9, 10–17, 18–25, 26+), «типовые серии» (панель, 5 и 9 этажей; кирпичная сталинка 5–8 этажей; монолитная высотка).
2. **Target encoding (OOF, со сглаживанием):** средняя `log(ppm)` по District, District×Age, District×Walls, District×«этажность», по «псевдо-дому». Плюс размеры групп (count).
3. **kNN и дубли:** OOF-цена ближайших похожих квартир и точное совпадение с train как признак или постобработка.
4. **Внешние данные (статичный CSV):** координаты центра района, расстояние до Кремля, азимут (запад дороже востока), расстояние до ближайшего метро, рыночная цена м² по районам из открытых источников, площадь и население района, «престижность».
5. **Отбор признаков:** по приросту CV, permutation importance, SHAP.

### Этап 5. Модели

| Модель | Зачем |
|---|---|
| Ridge/Lasso на one-hot и взаимодействиях | Сильная интерпретируемая база, разнообразие в ансамбле |
| LightGBM | Быстрый и сильный, основной кандидат |
| CatBoost | Сильный на категориях благодаря ordered TE, часто лучший на таких данных |
| XGBoost | Ещё один бустинг для разнообразия |
| RandomForest / ExtraTrees | Слабее, но иначе ошибаются |
| kNN-регрессия | Хорош на «соседях» и дублях |
| MLP с эмбеддингами районов | Опционально, если останется запас по времени |

Лоссы: L2 (совпадает с метрикой) и Huber/RMSE с весами.

### Этап 6. Тюнинг и интерпретация

- **Optuna:** байесовский подбор гиперпараметров. Каждый следующий набор выбирается с учётом предыдущих результатов, поэтому поиск эффективнее перебора по сетке. Запускаем офлайн в `experiments/`, а в финальную тетрадь кладём уже найденные параметры, чтобы уложиться в 10 минут.
- **SHAP:** вклад каждого признака в каждый прогноз. Нужен, чтобы понять, какие признаки реально работают, и поймать утечки.

### Этап 7. Ансамбль и постобработка

- Усреднение одной модели по 3–5 сидам.
- Взвешенное среднее OOF-прогнозов разных моделей (веса подбираем на OOF).
- Стекинг: Ridge поверх OOF-прогнозов.
- Постобработка: подмешивание цены точного дубля из train, клиппинг к разумному диапазону.

### Этап 8. Финальная тетрадь и запуск

- `solution.ipynb`: загрузка → подготовка → признаки → обучение с фиксированными параметрами → ансамбль → `submissions/submission.csv`.
- `requirements.txt` с зафиксированными версиями.
- `.github/workflows/flats.yml`: `workflow_dispatch` → установка зависимостей → `jupyter nbconvert --execute` → сабмит как artifact и коммит в репозиторий.
- Проверка формата: 10 127 строк, столбцы `Id,Price`, без NaN и отрицательных значений.
